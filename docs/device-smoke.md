# 稳定版兼容性评估与真机记录

稳定发布可以由两种证据路径授权：完整真机证据，或维护者在理解剩余风险后作出的显式
自动化评估决策。两种路径都会经过完整 CI、包审计、浏览器矩阵和 registry 消费者验证；
评估路径不会把未执行的真机测试标记为“通过”。

## 1.0.0 发布决策

| 发布决策项   | 记录       |
| ------------ | ---------- |
| 维护者授权   | trsoliu    |
| 决策日期     | 2026-07-30 |
| 适用版本     | 1.0.0      |
| 自动化评估   | 通过       |
| 剩余真机风险 | 已接受     |

评估依据包括 Chromium、Firefox、WebKit 与移动视口的 Playwright 回归，Vite、Nuxt、React
和 Next 的干净 registry 消费者构建，SSR/类型/包内容/体积检查，以及不依赖 UA 的能力检测、
原生 controls 降级和协议中立 Bridge 设计。稳定发布仍必须在最终版本提交上重新跑完整门禁。

## 真机记录

| 环境                   | 必须检查                                                     | 状态                         |
| ---------------------- | ------------------------------------------------------------ | ---------------------------- |
| iOS 15.6+ WKWebView    | 用户手势播放、暂停、跳转、音频路由切换、前后台切换、销毁清理 | 未执行（维护者接受剩余风险） |
| Android 8+ WebView 96+ | 用户手势播放、格式回退、蓝牙路由、宿主生命周期、销毁清理     | 未执行（维护者接受剩余风险） |
| HarmonyOS 3/4 WebView  | 播放、跳转、原生 controls 降级、宿主 Bridge 回调             | 未执行（维护者接受剩余风险） |
| HarmonyOS NEXT ArkWeb  | 播放、跳转、能力探测、宿主 Bridge 回调、销毁清理             | 未执行（维护者接受剩余风险） |

这些场景的宿主生命周期、蓝牙/系统音频路由和 Bridge 集成无法由桌面浏览器完全证明，是本次
风险接受后仍然存在的边界。发现稳定版特有问题时，应先记录环境与复现证据，再通过补丁版本
修复；真机结果可以在发布后继续补充，但不能倒填为发布前证据。

发布工作流会解析本页，四个真机环境行必须始终保留。状态都精确为 `通过` 时采用真机证据
路径；评估路径的每行状态只能是 `通过` 或 `未执行（维护者接受剩余风险）`，并必须存在完整的
维护者决策表，包含授权人、ISO 日期、精确稳定版本、自动化评估 `通过` 与剩余风险 `已接受`。
`适用版本` 可以是适用所有包的单一版本，也可以是逗号分隔的完整 `包名@版本` 映射；后者用于 core 与
adapter 版本不同步的后续发布。决策必须精确覆盖工作流传入的所有 package manifest，防止旧授权
被后续版本复用。
